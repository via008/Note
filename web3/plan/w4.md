# 二、Day 1：重新理解 ERC-20

你之前已经问过 ERC-20，所以这一天不要花大量时间看定义。

只需要搞清楚：

## ERC-20 是什么？

它不是：

> 一个 Token。

而是：

> **一套 Token 合约应该遵循的接口规范。**

例如常见接口：

```solidity
balanceOf(address)
totalSupply()
decimals()
symbol()
name()
transfer(address,uint256)
approve(address,uint256)
allowance(address,address)
transferFrom(address,address,uint256)
```

你可以把它理解成：

```text
ERC-20
   ↓
规定了一组标准函数
   ↓
不同 Token 合约按照这个标准实现
   ↓
前端就可以用统一方式交互
```

这也是为什么 USDC、DAI、UNI 等不同 Token，都可以使用类似的：

```ts
balanceOf(...)
transfer(...)
approve(...)
```

# 三、Day 2：彻底搞懂 ABI

这是 W4 非常重要的一个知识点。

你需要建立：

```text
Solidity
   ↓
编译器
   ↓
ABI + Bytecode
```

ABI 可以理解成：

> **前端和智能合约沟通时使用的接口描述。**

比如 Solidity：

```solidity
function balanceOf(address account)
    public
    view
    returns (uint256);
```

ABI 会告诉前端：

```text
函数名：balanceOf

输入：
address

输出：
uint256

类型：
function
```

于是 viem 才知道：

```ts
readContract({
  address,
  abi,
  functionName: 'balanceOf',
  args: [address],
})
```

应该怎么编码。

官方 viem 文档也明确说明，`readContract` 会使用 ABI 对调用数据进行编码，并通过 Public Client 执行 `call`。([Viem][1])

---

## 这一天你必须搞清一个问题

### ABI 从哪里来？

三种主要情况：

```text
自己写 Solidity
    ↓
编译
    ↓
ABI

别人开发的项目
    ↓
项目 artifacts
    ↓
ABI

Etherscan 已验证合约
    ↓
Contract → ABI
```

**不要再认为“有合约地址就能自动得到 ABI”。**

：

```text
Contract Address
```

只是：

> **“这个合约部署在哪里。”**

而：

```text
ABI
```

是：

> **“我应该怎么和这个合约沟通。”**

两者完全不同。

## 这里一定要理解一个关键点

`writeContract` **不是**：

> “调用 Solidity 函数并马上得到执行结果”。

而是：

> **构造并发送一笔会修改链上状态的交易。**

viem 官方文档明确说明，`writeContract` 会通过 Wallet Client 发送交易，并返回 **Transaction Hash**；它本身并不保证合约执行最终成功。官方还建议在写操作前使用 `simulateContract` 进行模拟。([Viem][3])

所以：

```text
writeContract
       ↓
Transaction Hash
```

而不是：

```text
writeContract
       ↓
Success
```

这个区别你一定要记住。

## Receipt 是什么？

Receipt 是交易被执行后的结果信息。

例如：

```text

blockNumber
gasUsed
transactionHash

```

你之前使用的：

```ts

  hash,
})
```

本质就是：

> 根据 transaction hash 等待链上产生 transaction receipt。

viem 的底层 `getTransactionReceipt` 也是根据 transaction hash 获取 receipt。([Viem][4])

### 最后 45 分钟

完成复盘。

回答下面 8 个问题：

```text
1. ERC-20 到底是什么？
ERC-20 是以太坊上同质化代币的接口标准，规定了 token 合约应该提供哪些标准接口以及接口的行为。

2. ABI 到底解决什么问题？
ABI 解决了程序如何按照合约规定调用函数，以及如何解析合约返回的结果。

3. Contract Address 和 ABI 有什么区别？
合约地址解决了找谁，ABI解决了怎么说话。

4. readContract 和 writeContract 有什么区别？
readContract 用于执行只读的合约调用，通常不产生链上交易，因此用户不需要支付gas。

writeContract 用于发起会改变链上状态的交易，需要用户签名，并且交易被执行时需要支付gas。

5. 为什么 readContract 不需要用户签名？
因为它不是需要用户授权的状态变更交易。

6. writeContract 为什么需要钱包？
writeContract 发起的是状态变更交易，需要证明交易是由某个账户授权发起的，因此需要账户进行签名，通常还需要该账户支付gas。

7. Transaction Hash 和 Receipt 有什么区别？
Transaction Hash 是交易在区块链上的唯一标识，Receipt 是交易执行后的结果。

8. 为什么交易成功后需要重新读取 balance？
因为前端之前显示的是旧的链上状态，交易成功后链上的状态发生了变化，所以需要重新读取链上数据。

```

**这 8 个问题如果你能不用查资料回答清楚，W4 就算真正完成。**
