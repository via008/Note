# 一、本周学习重点

## 1. ABI 到底是什么

这是 W5 的第一重点。

你之前已经总结过：

> Contract Address 解决“找谁”，ABI 解决“怎么说话”。

W5 要继续往下挖一层。

理解：

```text
Solidity Contract
       ↓
     编译器
       ↓
      ABI
       ↓
前端根据 ABI 组织调用
       ↓
Ethereum Node
       ↓
Contract
```

重点理解 ABI 中这些东西：

```text
function
inputs
outputs
stateMutability
type
name
```

例如：

```ts
{
  name: 'balanceOf',
  type: 'function',
  stateMutability: 'view',
  inputs: [
    {
      name: 'account',
      type: 'address'
    }
  ],
  outputs: [
    {
      type: 'uint256'
    }
  ]
}
```

你需要知道：

* `inputs` 是什么
* `outputs` 是什么
* `view` 是什么
* `pure` 是什么
* `nonpayable` 是什么
* `payable` 是什么
* `function` 和 `event` 在 ABI 中有什么区别

---

# 二、搞清楚 ABI 从哪里来

这部分是你之前已经问过的问题，这周把它彻底搞清楚。

你的学习重点是：

```text
自己写 Solidity
       ↓
    编译
       ↓
ABI + Bytecode
```

以及：

```text
别人开发的合约
       ↓
项目 artifacts
       ↓
ABI
```

还有：

```text
已经部署并验证的合约
       ↓
Etherscan
       ↓
ABI
```

你需要真正理解：

> **ABI 不是开发者手写出来的 Web3 特殊配置，它本质上是 Solidity 合约编译后的接口描述。**

同时再次确认：

```text
Contract Address ≠ ABI ≠ Bytecode
```

这三个东西分别解决：

| 东西               | 解决什么问题      |
| ---------------- | ----------- |
| Contract Address | 合约在哪里       |
| ABI              | 怎么和合约交互     |
| Bytecode         | EVM 实际执行的代码 |

# 三、深入理解 readContract

总计划中 W5 明确要求使用 `readContract` 查询：

```text
decimals
symbol
name
totalSupply
balanceOf
```



但这次不要只是把这些字段读出来。

你需要回答：

### ① 为什么 `balanceOf` 可以直接读取？

因为它属于：

```solidity
view
```

不会修改链上状态。

所以：

```text
Frontend
   ↓
RPC
   ↓
Ethereum Node
   ↓
Contract
   ↓
返回结果
```

不需要：

```text
钱包签名
```

也不需要：

```text
用户支付 Gas
```

---

### ② `readContract` 到底发生了什么？

你需要能够画出：

```text
readContract()
      ↓
viem
      ↓
RPC request
      ↓
Ethereum Node
      ↓
EVM 模拟执行
      ↓
Contract
      ↓
返回结果
```

重点理解：

> **read 并不是“从某个 API 数据库里读取”。**

而是通过 RPC 请求节点，让节点执行一次合约调用并返回结果。

# 十六、W5 最重要的一条主线

这周不要把重点放在：

> “我又学了几个 wagmi Hook。”

而是建立下面这个认知：

```text
             Solidity
                 ↓
              Compiler
                 ↓
          ┌──────┴──────┐
          ↓             ↓
         ABI          Bytecode
          ↓             ↓
      前端接口描述    EVM执行代码
          ↓
       viem
          ↓
       wagmi
          ↓
        React
          ↓
         DApp
```

这实际上是你从 **“Web3 API 使用者”→“Web3 前端开发者”** 的第一个真正转折点。

而且 W5 不需要急着碰 `writeContract`，因为按照你的总计划，**W6 才专门处理 Write Contract + Transaction Lifecycle**；W7 再进入 Event / Log。

**所以 W5 的核心不是“做更多功能”，而是把 Contract Interaction 这层彻底吃透。**
